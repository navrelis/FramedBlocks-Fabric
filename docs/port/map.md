## 7. Java 17 constraints

## 8. Risks, ranked

1. **Model baking hook + ~160 hand-written model classes on FRAPI** (visual regressions only visible in game: culling, AO, tint indices, per-quad layers, item `getRenderPasses`, double blocks, overlays). Mitigation: reuse `platform/model` verbatim (API-identical), `ModifyBakingResult` mixin keeps upstream replacement code, port's client smoke harness with Indigo.
2. **Mixin targets vs 1.20.1** (~35 non-light mixins carried from 1.21.1 vanilla code; `defaultRequire 1` crashes at first load of a mismatching class, e.g. entity friction/sound, `FireBlock`, `PoweredRailBlock`, `RailState`, `MapItemSavedData.tickCarriedBy` at `isFramed`, `Boat`, `AbstractHorse`, `BeaconBlockEntity`). Mitigation: verify each against `mappings.tiny`/decompiled jars; run the gametest server early (applies common mixins) and a client launch (client mixins).
3. **Per-position light**: no vanilla/Forge-free path in 9.4.3; port store + mixins must be wired into `FramedBlockEntity`; light-thread safety (port needed O1 hardening); **Starlight-Fabric 1.20.1** (popular, replaces `BlockLightEngine`) would ignore our mixins: glowing framed blocks emit no light with it; no ScalableLux on 1.20.1. Document or add a Starlight mixin later.
4. **Sodium needs Indium** on 1.20.1 (Sodium 0.5.x has no FRAPI): without it framed blocks render only the base model via vanilla `getQuads`. Declare `suggests indium` + README note; test both Indigo and Sodium+Indium. Sodium also ignores `Block.shouldRenderFace`/`getLightColor` hooks (same limitation as the port).
5. **Plant survival redesign** (`IPlantable` gone) touches `IFramedBlock`, `AbstractFramedBlock`, 6 blocks, BEs, double-block `PlantablePredicate`; behaviour must match (sand, farmland, soul sand camo) while Forge `PlantType` semantics change to vanilla `canSurvive` semantics.
6. **BE sync / onLoad ordering** (marker-key dispatch on `BlockEntity.load`, `FreshBlockEntityQueue` vs Fabric `BLOCK_ENTITY_LOAD`, culling update tracker, deferred `checkCamoSolid`): the port had a BE-load hang (H1) and needed `BlockEntityLoadTests`.
7. **Hook coverage audit**: Forge patches many vanilla call sites silently (friction, sound type, explosion resistance, fire, ladders, step effects...); a missed one compiles fine and only shows as a behaviour difference. Use the Forge-patched jar diff / the list in section 2 as the checklist; every hook needs an owner + gametest.
8. **Tag/recipe data** (Fabric 1.20.1 old `c:` naming, several tags missing, recipes referencing absent tags fail silently at load): needs a data validation pass (the port's recipe presence self-test).
9. **Transfer semantics** (dupe/loss on hoppers/pipes with framed storage/bookshelf/powered saw, fluid camo with buckets): reuse the port's reviewed `platform/transfer`, add only per-BE registration; keep `TransferTests`.
10. **Test harness/gametest flakiness and structure naming** (plural `structures`, 100-tick budget, light timing) plus large mechanical rename (assets/data/lang/JSON ids) done right once in task A.
