# Adding a new block type to FramedBlocks Fabric (1.21.1) - complete touch-point checklist

Baseline: branch `s-map` (cut from `mc/1.21.1`, HEAD `5f843723f`), upstream FramedBlocks 1.21 branch version 10.5.3 ported to Fabric.
`B` below = `src/main/java/xfacthd/framedblocks`, `R` = `src/generated/resources`, mod id/namespace = `framedblocks_fabric`.
Facts in this file were read from the code in this worktree; things marked **(unverified)** were not run here.

## 0. Ground rules of this port (read first)

* **There is NO datagen and NO codegen source in this repo.** Both were deleted in the port (commit `ad1afe64a`, `.knowledge/decisions.md`
  line 12, `report.md` line 69; upstream originals live in git history / `upstream/1.21`). Consequences:
  * `R` (= `src/generated/resources`, added as a resource dir in `build.gradle:76`) is **hand-maintained**. Every JSON that
    upstream's datagen would emit for a block must be written/copied by hand (section 7).
  * The ~83 `*SkipPredicate.java` files marked "machine-generated" are also hand-maintained now, but they **can still be
    regenerated** with upstream's generator, which is self-contained (section 5.3, verified).
* Registration is data driven by `BlockType` (enum) + `FBContent` (registry). Everything else (creative tab, item, color handler,
  render layer, client block effects, state cache, BE type of normal blocks, Jade, ghost renderer of doubles) is derived automatically
  from those two. Only the items in the checklist below are manual.
* 234 `BlockType`s exist today (84 double blocks, 30 without item). Test mod (`src/gametest`) enumerates `BlockType.values()` in
  many places (section 9), so a half-added type fails tests/`/fbtest` even if the game starts.

## 2. `BlockType` (`B/common/data/BlockType.java`)

Pattern (line 79 / 146 / 276):
```java
FRAMED_SLAB_EDGE   (false, false, false,  true,  true,  true, false, false, ConTexMode.FULL_EDGE, SlabEdgeShapes::generate),
FRAMED_PATH        ( true, false, false, false,  true,  true, false, false, ConTexMode.FULL_FACE, Block.box(0, 0, 0, 16, 15, 16))   // last constant, then ';' on line 277
```
Three ctor overloads: no shape (`ShapeGenerator.EMPTY`, block supplies shapes itself), `VoxelShape` (wrapped in `singleShape`; precondition
at line 301 rejects `waterloggable` with a full-cube shape), `ShapeGenerator` (e.g. `XShapes::generate`, called with all states).
Enum position = creative tab order (`FramedCreativeTab` iterates `values()`), `ordinal` indexes `BlockTypeMap`; the position is also checked by the
skip-predicate generator (section 5.3). Names are lower-cased as registry ids (`getName()`), so `FRAMED_X` => `framedblocks_fabric:framed_x`.

Argument meaning (in order; interface docs in `B/api/type/IBlockType.java`):

| # | arg | meaning / what you must also do |
|---|---|---|
| 1 | `canOcclude` (`canOccludeWithSolidCamo`) | block may become "solid" when a full-cube camo is inserted. `false` => `Properties.noOcclusion()`. `true` => block **must** have `FramedProperties.SOLID` (ctor `AbstractFramedBlock:57` does `setValue(SOLID,false)`, so a missing `builder.add(SOLID)` crashes at registration; double blocks get it from `AbstractFramedDoubleBlock`). Checked by `OcclusionPropertyConsistency`, `FramedBlockEntity.checkCamoSolid()`, `OcclusionTests` (warns if no `@TestedType` test). `FramedStorageBlock`/`FramedPathBlock` add it in `createBlockStateDefinition`; `FramedChestBlock` removes it again via `FramedUtils.removeProperty`. |
| 2 | `specialHitbox` | true for non-box shapes (slopes, prisms...): the VoxelShape is only an approximation and the client draws the outline with an `OutlineRenderer`. Requires a registration in `BlockOutlineRenderers` (`event.register(BlockType.X, new XOutlineRenderer())`); otherwise `BlockOutlineRenderer` logs an error once and the vanilla box is drawn; `SpecialShapeRendererPresence` self-test checks both directions (flag set but no renderer, renderer but no flag; `RegisterOutlineRenderersEvent` itself throws if the flag is false). Renderers: `draw(state, poseStack, consumer)` using `OutlineRenderer.drawLine`, `rotateMatrix` (default rotates by `FACING_HOR`). |
| 3 | `specialTile` | the block uses its own `BlockEntityType` (not the shared `framed_tile` / `framed_double_tile`). Required for BE blocks (chest, tank...), hoppers, signs, doors and most double blocks with custom BE logic. Excludes the block from `getDefaultEntityBlocks()/getDefaultDoubleEntityBlocks()` (`FBContent:801-826`). Checked by `BlockEntityPresence` (warn if block has 0 or >1 valid BE types). |
| 4 | `waterloggable` | block must put `BlockStateProperties.WATERLOGGED` into its state definition (ctor registers default `false`; `FramedBlock`s use `PlacementStateBuilder...withWater()` for placement). `WaterloggingPropertyConsistency` checks the property matches the flag. | 5 | `blockItem` | `registerBlock` also registers an item with the same id (via `IFramedBlock.createBlockItem()`, default `BlockItem`; override for special placement, e.g. `FramedSlabBlock:66` returns a `FramedSpecialBlockItem`). `false` for hidden/combined blocks (double slab/panel, segments): then you must provide `getCloneItemStack` (see `FramedDoubleSlabBlock:28`) and a loot table that drops the real items. | 6 | `allowIntangible` | Phantom Paste can make the block pass-through (`getShape` returns empty via `isIntangible`). | 7 | `doubleBlock` | two camos / two model parts; see section 6. Such types: block implements `IFramedDoubleBlock`, BE implements `IFramedDoubleBlockEntity`, side-skip predicate is `SideSkipPredicate.FALSE`, **must not** appear in the generator's `KNOWN_TYPES`. Also makes the camo-application recipe consume two camos. |
| 8 | `lockable` | block supports the state lock (Framed Key/Screwdriver flow): block needs `FramedProperties.STATE_LOCKED` and must call `updateShapeLockable(...)` in `updateShape`; `LockingPropertyConsistency` checks the flag/property pair. Use `WrapHelper.IGNORE_*_LOCK` in the model wrapper. |
| 9 | `minCTMode` | connected-textures support: `null` = none; `ConTexMode.FULL_FACE` (only full faces connect), `FULL_EDGE` (+ edges where neighbour covers a full face), `DETAILED` (+ faces where own SideSkipPredicate is true) - docs in `B/api/predicate/contex/ConTexMode.java`. | 10 | `shape` / `shapeGen` | see section 3. In non-production (dev) environments the generator is wrapped in a `ReloadableShapeProvider` so shapes hot-reload with `/reload`. |

## 3. Shapes (`B/api/shapes/*`, `B/common/data/shapes/*`)

* `ShapeGenerator.generate(ImmutableList<BlockState> states) -> ShapeProvider` is called from `AbstractFramedBlock`'s ctor with *all* states,
  so per-state shapes are precomputed. Typical implementation (`SlabEdgeShapes`): loop states, read properties, `builder.put(state, CommonShapes.X.get(key))`,
  `return ShapeProvider.of(builder.build())`.
* Cache helpers: `CommonShapes` (`ShapeCache.create / createEnum / createIdentity`, `DirBoolKey`, `SLAB_GENERATOR`, `PANEL_GENERATOR`),
  `MoreCommonShapes` in `common/data/shapes`, rotation helpers in `ShapeUtils` (`makeHorizontalRotations(shape, srcDir, map)`,
  `makeHorizontalRotationsWithFlag(shapeFalse, shapeTrue, srcDir, map, KeyCtor)`, `rotateShapeAroundX/Y/Z`, `or/and(Unoptimized)`).
  `ShapeCache`s register themselves with `ShapeReloader` for dev reload.
* Separate occlusion shape (when the shape used for face culling differs from the collision/hit shape): implement `SplitShapeGenerator`
  (`generateOcclusionShapes`), `BlockType` detects it (`separateOcclusionShapes`).
* If the type uses `ShapeGenerator.EMPTY` (stairs, walls, doors...) the block must override `getShape` itself **and**
  `doesBlockOccludeBeaconBeam` (otherwise `AbstractFramedBlock:204` throws `NullPointerException` with a "handles shapes itself" message).
  For all other blocks the beacon-beam flag is computed from the shapes (`computeBeaconBeamOcclusion`: shape must cover the 6x6 column x 5..11).
* Unlike upstream's later versions there is no extra "flip" machinery; mirror/rotate live in the block (next section).

## 4. Block class (`B/common/block/**`, base `B/api/block/AbstractFramedBlock.java`, `B/api/block/IFramedBlock.java`)

Hierarchy: `Block` -> `AbstractFramedBlock` (api, `B/api/block/AbstractFramedBlock.java`; implements `IFramedBlock`, `SimpleWaterloggedBlock`; builds shapes, `GLOWING` + `PROPAGATES_SKYLIGHT`
properties, camo drops/occlusion/shade/hover text) -> `FramedBlock` (common; `createProperties(type)`, `isPathfindable=false` except cube)
-> your block. Doubles: `FramedBlock` -> `AbstractFramedDoubleBlock` (adds `SOLID`, implements `IFramedDoubleBlock`). Blocks that must subclass a vanilla
class (`PoweredBlock`, `HopperBlock`, `RedstoneTorchBlock`, doors, rails...) `implements IFramedBlock` directly and copy the boilerplate
(`FramedRedstoneBlock`: `useItemOn -> handleUse`, `setPlacedBy -> tryApplyCamoImmediately`, `updateShape/neighborChanged -> updateCulling`,
`useShapeForLightOcclusion/getOcclusionShape/getVisualShape/getShadeBrightness/propagatesSkylightDown`, `getDrops -> getCamoDrops`,
`appendHoverText -> appendCamoHoverText`, `getShape` with `isIntangible`, `getBlockType`, `createProperties(type)`); such classes (not `AbstractFramedBlock` subclasses) are registered with Jade via `getJadeTargetClass()` (default: the own class; override if a shared vanilla-derived class is reused by several blocks).

Worked example (`FramedSlabEdgeBlock`, 86 lines): ctor `super(BlockType.FRAMED_SLAB_EDGE)` + `registerDefaultState(... TOP,false)`;
`createBlockStateDefinition: super + builder.add(FACING_HOR, TOP, WATERLOGGED)` (note: `GLOWING`/`PROPAGATES_SKYLIGHT` come from super; `SOLID` only if the type needs it);
`getStateForPlacement: PlacementStateBuilder.of(this, ctx).withHorizontalFacing().withTop().withWater().build()` (more builders in `B/api/block/PlacementStateBuilder.java` and `B/common/block/ExtPlacementStateBuilder.java`: `withTargetFacing`, `withHalfFacing`, `withClickedAxis`, `withHorizontalFacingAndSlopeType`, `withCornerRotation`, `withCrossRotation`, `withFront`, `withRight`, `withCustom(BiFunction)`);
`isPathfindable` re-enabled for water; **`rotate(state, face, rot)`** (wrench: sneak = counter-clockwise; `IFramedBlock.handleUse` calls `rotate(state, hit, rot)`; side faces cycle the secondary property), `rotate(state, Rotation)` (vanilla/structure; delegate to the first), **`mirror`** (`Utils.mirrorFaceBlock(state[, prop], mirror)` / `Utils.mirrorCornerBlock`, `B/api/util/Utils.java:313-372`), **`getItemModelSource()`** (state whose wrapped block model is reused as item model, `null` = use the item JSON; needed by `ModelWrappingHandler.updateItemModelSource` and by `FramedBlockColor`), **`getJadeRenderState(state)`** (state drawn in the Jade tooltip; `JadeRenderStateErrors` self-test).
Properties: shared `FramedProperties` (`B/api/block/FramedProperties.java`: `FACING_HOR`, `FACING_NE`, `TOP`, `OFFSET`, `X/Y/Z_AXIS`, `SOLID`, `PROPAGATES_SKYLIGHT`, `GLOWING`, `STATE_LOCKED`, `Y_SLOPE`, `COPYCAT_STYLE`; note `Y_AXIS` is spelled `y_asix` in blockstate strings) and mod-specific `PropertyHolder` (`B/common/data/PropertyHolder.java`, enum properties in `B/common/data/property/*`: `SLOPE_TYPE`, `CORNER_TYPE`, `ROTATION` (HorizontalRotation), `FACING_AXIS`, `FACING_DIR`, `TOP_HALF`, `FRONT`, `RIGHT`, `ALT_TYPE`, `THICK`, ...). New properties go into `PropertyHolder` (+ enum in `property/` implementing `StringRepresentable`). Mind property-name clashes: several properties share the string name `type`/`rotation` and are distinct objects.
Other overridable hooks with defaults in `IFramedBlock` (positions in `B/api/block/IFramedBlock.java`): `getLightEmission` (185), `getSoundType`, `getFriction`, flammability (`isFlammable`, `getFlammability`, `getFireSpreadSpeed`, `isFireSource`), `handleBlockLeftClick`, `isIntangible` (386), `isCamoEmissiveRendering` (395), `shouldPreventNeighborCulling`, `getComponentAtEdge/getComponentBySkipPredicate` (CT lookup in doubles), `lockState/updateShapeLockable`, `getMapColor`, beacon colour (`getBeaconColorMultiplier`, `doesBlockOccludeBeaconBeam`), `canSustainPlant`, `isLadder`, `getJadeRenderScale`, `shouldApplyGuiTransformFromModel`. On Fabric these are not NeoForge extension methods: the vanilla call sites are patched by mixins that dispatch through `B/platform/util/BlockHooks.java` (+ `mixin/*`), so overriding them in your block is enough, no registration.

## 5. Predicates and culling

### 5.1 FullFacePredicate (`B/api/predicate/fullface/FullFacePredicate.java`, registry `facepreds/FullFacePredicates.java`)
`put(BlockType.FRAMED_X, FullFacePredicate.FALSE|TRUE|Y_AXIS|TOP|DOWN|HOR_DIR|...)` or `new XFullFacePredicate()` (classes in `facepreds/<group>`; `.and/.or` composable).
Semantics: true for sides where the block's face is a complete 16x16 unmodified camo face. `StateCache` (built per state at `TAGS_LOADED`, see `StateCacheBuilder`) stores it as a bitmask:
the model passes quads of such faces through unmodified (`FramedBlockModel:86`: `xformDirFilter = d -> !isFullFace(d)` unless `Geometry.transformAllQuads()`), `CullingHelper.hidesNeighborFace`
uses it to hide neighbour faces, connected textures use it for `FULL_FACE` mode. Wrong value = visual bugs only (silent).
Examples: slab edge `FALSE` (line 64), path `DOWN` (261), double slab `Y_AXIS` (60), glowing cube `TRUE` (228).

### 5.2 ConnectionPredicate (`B/api/predicate/contex/ConnectionPredicate.java`, registry `conpreds/ConnectionPredicates.java`)
`put(BlockType.FRAMED_X, ConnectionPredicate.FULL_EDGE|FULL_FACE|FALSE | new XConnectionPredicate())`. Two methods: `canConnectFullEdge(state, side, @Nullable edge)`
(edge==null means the whole face; true if that edge of that side spans the full width at the block's outer bounds) and `canConnectDetailed(state, side, edge)` (same but for faces/edges that are
only covered via the block's own skip predicate). Ref: `conpreds/slab/SlabEdgeConnectionPredicate.java`, `conpreds/misc/PathConnectionPredicate.java`. Only evaluated if `minCTMode != null`.
`StateCache` precomputes all (side, edge) masks; `StateCacheValidity`/`DoubleBlock*Consistency` self-tests sanity-check them.

### 5.3 SideSkipPredicate (`B/api/predicate/cull/SideSkipPredicate.java`, registry `skippreds/SideSkipPredicates.java`)
`test(level, pos, state, adjState, side)` = "does the neighbour framed block (same camo) hide this side of me". Used by `CullingHelper` (via `IFramedBlock.runOcclusionTestAndGetLookupState`, which for doubles tests both components of the neighbour) and, in DETAILED mode, by connected textures.
Registry rules: `put(BlockType.FRAMED_X, X)` where X is `SideSkipPredicate.FALSE` (always for doubles, tanks, cubes...), a hand-written class (`PathSkipPredicate`, 17 lines: `!isY(side) && adjState.getBlock() == state.getBlock()`), or a generated class (`new SlabEdgeSkipPredicate()`). `BlockTypeMap` returns the default (`FALSE`) for unmapped types and in dev logs `Type 'X' missing mapping in 'SideSkipPredicates'` (`BlockTypeMap.check`) - forgetting is silent in production.

**Generated predicates.** Pattern (`skippreds/slab/SlabEdgeSkipPredicate.java`): `@CullTest(BlockType.FRAMED_SLAB_EDGE) final class ...` with one `switch (blockType)`
`case FRAMED_OTHER -> testAgainstOther(<props of self>, adjState, side)` for every other type that shares at least one *dir id*, and one `@CullTest.TestTarget(BlockType.OTHER) private static boolean testAgainstOther(...)`
per target, built from `SlabDirs.SlabEdge.getHalfDir(dir, top, side).isEqualTo(SlopeDirs.HalfSlope.getHalfDir(adjDir, adjTop, adjRight, side.getOpposite())) || ...`. The `*Dirs` classes (`skippreds/<group>/XDirs.java`, value classes `HalfDir`, `CornerDir`, `TriangleDir`, `QuarterTriangleDir`, `DiagCornerDir`, `HalfTriangleDir`, `TubeOpening` in `skippreds/`) are **hand-written** geometry descriptors: for a given block state and side they return a descriptor of the face shape that lies on that side's plane (e.g. `HalfDir.fromDirections(normal, edge)` = half-size face at that edge, `NULL` = nothing there). Two predicates compare descriptors with `isEqualTo`.
Adding a type therefore means: (a) write `XDirs.getXDir(props..., side)` methods describing each of X's faces, (b) add a `KNOWN_TYPES` entry that lists X's state properties and which dir *ids* each descriptor carries (types are tested against each other iff they share an id, e.g. `half_xz_hor`), (c) run the generator for X, which writes `XSkipPredicate` **and rewrites every existing predicate that now needs a new `case`/`testAgainstX`** (upstream commit d58496660 "Layered Cube": +15 lines in 29 files; 49af28240: 40 files), (d) register `new XSkipPredicate()`.
Self-test `SkipPredicatePresenceConsistency` (SelfTest, log only) warns if A tests against B but B has no reverse test (unless `oneWay = true`) or a type lacks a self-test; `/fbtest skippredicates consistency|errors|redundancy` (dev client/world only, not part of `build`) brute-forces all state combinations.

**Generator (verified to work against this repo).** Source: `upstream/1.21:src/test/java/xfacthd/framedblocks/codegen/{SkipPredicateGenerator.java, impl/skippreds/SkipPredicateGeneratorData.java, impl/skippreds/SkipPredicateGeneratorImpl.java}` (~2000 lines, only depends on `java.*` and two JetBrains annotations `@Nullable`, `@Contract`).
It writes to `./src/main/java/xfacthd/framedblocks/common/data/skippreds/` relative to the working directory and **parses `./.../common/data/BlockType.java` by text** (validates that every *non-double* enum constant is present in `KNOWN_TYPES` **in the same order** and that no double block is; the 7th ctor argument is read as `doubleBlock`, so keep one constant per line in the existing format). ## 6. Double blocks (reference `FramedDoubleSlabBlock`, `FramedDoubleSlopeBlock`, `B/common/block/IFramedDoubleBlock.java`)

BlockType flags: `canOcclude=true`, `doubleBlock=true`, usually `Shapes.block()` or a union (`FRAMED_DOUBLE_SLAB`: `( true,false,false,false,true,true,true,false,FULL_FACE,Shapes.block())`, line 75). `blockItem=false` for compositions of two existing items (slab/panel) - then loot uses `dropMultipleWithCamo`-style tables (upstream `FramedLootTableProvider`: JSON with two pools, `split_camo` function index 0/1; the generated JSON of `framed_double_slab` is the model) and `getCloneItemStack` returns the single item.
Block: `extends AbstractFramedDoubleBlock`, implement the four `@OverrideOnly` methods (all evaluated once per state into `DoubleBlockStateCache`, self-tests `StateCacheValidity`, `DoubleBlockCamoConnectionConsistency`, `DoubleBlockSolidSideConsistency`):
* `calculateBlockPair(state) -> Tuple<A,B>` the two single-block states the model is composed of (used for model parts, shapes of each half, skip-predicate lookup `runOcclusionTestAndGetLookupState`, CT component lookup, hit detection).
* `calculateTopInteractionMode(state) -> DoubleBlockTopInteractionMode {FIRST, SECOND, EITHER}`: which camo's sound/friction/particles/map colour apply for the top face (landing/running/stepping, `FramedDoubleBlockEntity.getMapColor/getCamoFriction`).
* `calculateCamoGetter(state, side, @Nullable edge) -> CamoGetter {NONE, FIRST, SECOND}`: which camo shows on a face/edge (CT, particles, flammability...). `calculateSolidityCheck(state, side) -> SolidityCheck {NONE, FIRST, SECOND, BOTH}`: which camos must be solid for that side to count as solid (plants, `SOLID` property).
* `newBlockEntity`: `final`, returns `new FramedDoubleBlockEntity(pos, state)` for plain doubles (BE type `framed_double_tile`, registered once in `FBContent:428-433`, contains every double block with `specialTile==false`), else the type's own subclass (`FramedDoubleSlopeBlockEntity`: ctor `super(FBContent.BE_TYPE_DOUBLE_FRAMED_SLOPE.value(), pos, state)`; overrides `hitSecondary(hit, look, eye)` when the default shape-clip test between the two halves is wrong) and then `specialTile=true` + a register line:
```java
public static final Holder<BlockEntityType<?>> BE_TYPE_DOUBLE_FRAMED_SLOPE = registerBlockEntity(FramedDoubleSlopeBlockEntity::new, BlockType.FRAMED_DOUBLE_SLOPE);  // FBContent:434
```
(`registerBlockEntity(factory, BlockType...)` names the type after the first type and, in dev, adds it to `DOUBLE_BLOCK_ENTITIES` for the debug renderers).
* Client: `wrapDoubleModel(FBContent.BLOCK_FRAMED_DOUBLE_SLAB, NullCullPredicate.ALWAYS, WrapHelper.IGNORE_SOLID)` in `FBClient` (no Geometry class): `NullCullPredicate` (`ALWAYS/NEVER/ONLY_LEFT/ONLY_RIGHT`, or custom per-state predicates as in `FramedDoubleSlopeSlabBlock.NULL_CULL_PREDICATE`) says which half's cull-less quads are dropped because they are covered by the other half; optional `ItemModelInfo` (`DoubleBlockItemModelInfo.INSTANCE / Y_HALF_UP`, `AdjustableDoubleBlockItemModelInfo`). Ghost (blueprint) rendering and debug renderers are attached automatically for all double blocks; client block effects use `FramedDoubleBlockRenderProperties` automatically.
* Predicates: side skip `FALSE`, full face / connection predicates as for singles (`DoubleSlabConnectionPredicate.INSTANCE`, `FullFacePredicate.Y_AXIS`). Blueprint: only needed if copy/paste must consume other items than the double item (`DoubleSlabCopyBehaviour` registered in `common/data/BlueprintBehaviours.java:14`); adjustable doubles use `DummyDataHandlingCopyBehaviour`.
* Tests: `BeaconTintTests`/`LightSourceTests` `getCamoSides` switch decides which faces get camos in the generated tests (default for doubles `DOWN, UP`; add your type if its two parts are split along X/Z).

## 8. Client side (`B/client/**`)

* **Geometry** (`B/client/model/<group>/FramedXGeometry.java`, base `B/api/model/geometry/Geometry.java`): ctor takes `GeometryFactory.Context ctx` (`ctx.state()` - the *merged* state, `ctx.baseModel()`, `ctx.modelLookup()`, `ctx.textureLookup()`); implement `transformQuad(QuadMap quadMap, BakedQuad quad)` which is called for every quad of the camo block's model whose cull-face is *not* a full face (section 5.1). Never mutate the source quad; use the fluent `QuadModifier.of(quad).apply(Modifiers.cutTopBottom(dir, .5F)).applyIf(Modifiers.setPosition(.5F), cond).export(quadMap.get(cullFaceOrNull))` (`B/api/model/quad/QuadModifier.java`; `tintIndex`, `shade`, `ambientOcclusion`, `derive()` for multiple outputs; `Modifiers` in `B/api/model/quad/Modifiers.java`: `cut`, `cutTopBottom`, `cutSideUpDown`, `cutSideLeftRight`, `cutSide(minXZ,minY,maxXZ,maxY)`, `cutPrismTriangle`, `cutSmallTriangle`, `makeHorizontalSlope`, `makeVerticalSlope`, `offset`, `setPosition`, `rotate`, `rotateCentered`, `scaleFace`, `applyFullbright`, `applyLightmap`; `export(list)` adds the (re-assembled) quad unless any modifier failed, e.g. a cut that removes the whole face). `quadMap.get(null)` = quads with no cull face (inset/internal faces, always rendered), `quadMap.get(dir)` = quads culled when the neighbour on `dir` hides them. Examples: `slab/FramedSlabEdgeGeometry` (cuts + inset), `cube/FramedPathGeometry` (15 lines), `cube/FramedGlowingCubeGeometry` (post-processing). Optional overrides: `transformAllQuads`, `useBaseModel`/`forceUngeneratedBaseModel`/`getBaseModel` (use the JSON model when no camo is applied, e.g. chests), `useSolidNoCamoModel`, `getAdditionalQuads` (non-camo extra quads, e.g. lantern chain, `getAdditionalRenderTypes`), overlay quads, `makeCacheKey` (if output depends on `ModelData` beyond camo+CT), `postProcessUncachedQuads`, `useAmbientOcclusion`, `getItemModelInfo`, `getAuxModelData`.
* **Registration**: in `FBClient.onRegisterModelWrappers` add `WrapHelper.wrap(FBContent.BLOCK_FRAMED_X, FramedXGeometry::new, WrapHelper.IGNORE_WATERLOGGED);`. The 3rd argument is the set of properties that do **not** change the geometry (`IGNORE_ALWAYS` = GLOWING+PROPAGATES_SKYLIGHT, `+WATERLOGGED`, `+SOLID`, `+STATE_LOCKED` variants, `IGNORE_DEFAULT` = SOLID+WATERLOGGED+always, `IGNORE_DEFAULT_LOCK`, see `WrapHelper:20-28`) or a custom `StateMerger` (`StateMerger.IGNORE_ALL`, `.ignoring(set)`, per-block mergers like `FramedStairsBlock.StairStateMerger`, `FramedButtonBlock.STATE_MERGER`). States equal after merging share one baked model, so ignoring a property that *does* change geometry silently renders wrong; ignoring too little only wastes memory. `WrapHelper.copy(block, srcBlock, merger)` reuses another block's models (waterloggable pressure plates), `wrapSpecial` for custom `ModelFactory`, `wrapDoubleModel(...)` (private helper in `FBClient`) for doubles. Registration is posted once from `ModelWrappingManager.init()` (called in `FBClient.onInitializeClient`); unregistered framed blocks keep their raw JSON model *without camo* (silent). Debug: DevTools config `isStateMergerDebugLoggingEnabled` logs unhandled properties per block, `ModelCounter` debug line prints wrapped model counts.
* **Automatic for every registered `IFramedBlock`**: block/item colour handler (`registerColorProviders`, except flower pot/target), `BlockRenderLayerMap` cutout (`registerRenderLayers`), client block effects (`registerBlockEffects`; add a `case` there only for custom effects), state caches, Jade provider (`FramedJadePlugin`), JEI/REI/EMI (generic, enumerate nothing per block).
* **Item model**: `getItemModelSource()` state is baked through the same geometry (gui/hand transform from the base JSON, `Geometry.getItemModelInfo()`, `shouldApplyGuiTransformFromModel()`); special item renderers only for the tank (`BuiltinItemRendererRegistry`, `TankItemRenderer`, `FramedTankItemModel`). Thin items (flat blocks) just use the cube parent in 1.21.1.
* BE renderer/screen registrations (chest, sign, tank, item frame): `FBClient.registerBlockEntityRenderers()` (169), `registerMenuScreens()` (155).

### 10.3 Light / emissive (`FRAMED_GLOWING_CUBE`, glowstone, lamps)
* `FRAMED_GLOWING_CUBE` (`FramedGlowingCubeBlock`, 35 lines) is a plain cube; the "glow" is purely visual: `FramedGlowingCubeGeometry extends FramedCubeGeometry` overrides `hasUncachedPostProcessing()`+`postProcessUncachedQuads` (replaces quads with `ExtendedBakedQuad`s whose lightmap is forced to max via `QuadTransformers.settingMaxEmissivity()`) and `useAmbientOcclusion -> TriState.FALSE`. Block entity camo can additionally emit light like any framed block.
* Camo/glowstone light (all framed blocks): `FramedBlockEntity.glowing` (glowstone dust) / camo `getLightEmission` => `getLightValue()` => `AuxLight.set(level, pos, value)` (`B/platform/light/AuxLight.java`; per-chunk store `AuxLightMap`, saved in chunk NBT key `framedblocks_fabric:aux_light` via `mixin/light/MixinChunkSerializer`, rebuilt from BEs when a chunk loads; the store hangs off chunks through the `AuxLightHolder` duck interface implemented by `MixinChunkAccess/MixinLevelChunk/MixinImposterProtoChunk`; client chunk reads `AccessorRenderChunkRegion`/`MixinLevelRendererLight`). The `GLOWING` blockstate property is the flag that makes the light engine look at the store; light engine hooks: `MixinBlockLightEngine`, `MixinLightEngine`, optional Starlight compat. The engine consults `IFramedBlock.getLightEmission(state, level, pos)` for every framed block and **ignores `state.getLightEmission()`**: default implementation returns `GLOWING ? AuxLight.get : 0`.
  => **A framed block with its own light level (lamp, torch, lantern) must (a) set `.lightLevel(state -> ...)` in its properties and (b) override `getLightEmission` as `Math.max(state.getLightEmission(), IFramedBlock.super.getLightEmission(state, level, pos))`** (pattern: `FramedTorchBlock:86`, `FramedLanternBlock:93`, `FramedRedstoneTorchBlock:93`). Without (b) it emits 0 in-game although the state reports light (silent).
* Emissive rendering: `Properties.emissiveRendering(IFramedBlock::isEmissiveRendering)` (set in `createProperties`) asks `isCamoEmissiveRendering` (camo-based); cube-style fullbright needs the geometry approach above; `LightSourceTests` skips self-emitting types via `isNotSelfEmitting`.
* Redstone: `FramedRedstoneBlock extends PoweredBlock implements IFramedBlock` for a block that emits power; a redstone lamp would extend `RedstoneLampBlock` the same way (add `LIT`, light level, `getLightEmission` override).

## 12. Pitfalls (things that break silently)

1. Missing `FBContent.registerBlock` => `byType` NPE in creative tab/tests; missing **model wrapper** => block renders its raw JSON model without camo, no error; missing `BlockOutlineRenderers` entry for `specialHitbox` => one logged error, box outline.
2. Predicate registries return a default (`FALSE`) for unmapped types; only dev logs `Type ... missing mapping`. Wrong `FullFacePredicate` or `StateMerger.ignore` => visual bugs (holes, z-fight, wrong shape) without any exception.
3. Flag/property mismatches: flag set but property not added => crash at registration; property added but flag false => only a self-test WARN (and `waterlogged` blocks without `SimpleWaterloggedBlock` hooks etc.).
4. `ShapeGenerator.EMPTY` without overriding `doesBlockOccludeBeaconBeam` => NPE on beacon queries; shapes are computed for *all* states inside the `AbstractFramedBlock` ctor, i.e. the state definition must be complete by then: `createBlockStateDefinition` is called from `Block`'s own constructor, **before the subclass' field initializers run**, so it may only reference static properties/constants; `registerDefaultState` in your own ctor (after `super(...)`) is fine.
5. `StateCache`/`getCache(state)` before `TAGS_LOADED` (`FramedBlocks.onCommonSetup`) throws "called too early": do not touch caches in constructors/static init. The three predicate registries are filled in `FramedBlocks.onInitialize` (lines 94-96) after `FBContent.init()`, so predicate constructors may use `FBContent`, but not state caches.
6. Light: own `lightLevel` without the `getLightEmission` override emits nothing (section 10.3). Aux light is stored per chunk; never call `AuxLight.set` off the owning thread.
7. Codegen: regenerating can overwrite hand-adjusted predicates and the two upstream-lagging files (section 5.3); the generator reads `BlockType.java` as text (format and order!). Never edit "machine-generated" classes by hand if you plan to regenerate. Do not put double blocks into `KNOWN_TYPES`.
8. Blocks extending vanilla classes: Fabric does not have NeoForge's extension methods; vanilla checks like `state.is(Blocks.X)`/`BlockEntityType.X.isValid` (crafting menu `stillValid`, barrel's BE class, hopper) ignore your block; fire/friction/explosion/sound hooks only work through `BlockHooks` mixins for `IFramedBlock` implementers.
9. Data: missing loot table => no drop; missing lang key => raw key; missing axe tag => slow mining; missing saw/crafting recipe => self-test warn only; JSON `render_type` is ignored (layers via `BlockRenderLayerMap`); new JSON must be UTF-8, 2-space indented, no trailing newline needed (match datagen style to keep diffs small).
10. SelfTest results and `RecipePresence` are **log-only**: a green `build` does not prove they pass. `BeaconTintTests`/`LightSourceTests` are *required* generated tests: an unlisted non-tinting/self-emitting type fails the build.
11. `SOLID`: only blocks with `canOcclude` have it; `FramedBlockEntity.checkCamoSolid` and models assume it; remember `IGNORE_SOLID` vs `IGNORE_DEFAULT` choice in the wrapper.
12. Block entities: every framed block (also crafting table/lamp) needs a `FramedBlockEntity` (client test fails otherwise). Ordinary `specialTile=false` blocks are added automatically to `framed_tile`/`framed_double_tile` via the supplier evaluated at BE registration (after blocks); `specialTile=true` without own BE registration => `BlockEntityPresence` warn and `newBlockEntity` NPE.
13. Item-less types (`blockItem=false`): need `getCloneItemStack`, a loot table dropping the real item(s), and are skipped by the creative tab and `RecipePresence`.
14. Dev-vs-production behaviour differs (`Platform.isProduction()`): reloadable shape providers, the state-cache reload listener and `BlockTypeMap.check` only exist in dev. All Gradle run tasks are dev environments, so production-only paths (plain `ShapeProvider`s, no mapping check) are exercised only by the built jar in a normal launcher.
