# Decisions

- Remotes: `upstream` = XFactHD/FramedBlocks, `origin` = navrelis/FramedBlocksFabric (created private; user can make it public). Reason: user approved repo creation, visibility was not specified, private is reversible.
- License stays LGPL v3 (upstream license; cannot be relicensed to plain GPL without reason, and user asked to keep it). Ship both LGPL v3 and the GPL v3 text it references.
- Working tree was empty at session start; restored from HEAD with `git restore`. Nothing overwritten.
- Mod id: `framedblocks_fabric` (user asked for a new id). Java package stays `xfacthd.framedblocks` to keep upstream headers and mergeability. Saved worlds from the NeoForge mod are not compatible.
- Toolchain: Loom 1.15.5 on the existing Gradle 9.2.1 wrapper and JDK 21 (newer Loom needs newer Gradle / possibly Java 25).
- Config: Forge Config API Port 21.1.6, bundled jar-in-jar (MPL-2.0), keeps `ModConfigSpec` code unchanged.
- No Porting Lib: 1.21.1 builds are unreleased betas; own small platform layer instead.
- Rendering: Fabric Rendering API (Sodium 0.6+ implements it natively, no Indium).
- Removed integrations (no Fabric 1.21.1 build): Create, Applied Energistics 2, Building Gadgets.
- Datagen: the committed generated resources are kept and patched; the NeoForge datagen DSL is not ported unless something needs regenerating.
- Precision override B1 (Opus): rendering core, errors are subtle and only visible in game.
- Precision override C2 (Opus): light engine mixins, mistakes cause persistent light corruption in worlds.
- Compat compile versions capped by Loom 1.15.5 (rejects jars built with a newer Loom): JEI 19.56.0.441 instead of 19.64, Amendments 2.0.15 instead of 2.1.11; Puzzles Lib and Moonlight not on the classpath (not needed to compile). All integrations are compile-only and optional (`suggests`).
- Athena hook removed: Fabric Athena models compute connections in `emitBlockQuads`, there is no model-data property to forward. Connected textures on camo depend on the foreign-model capture in `ModelBridge`.
- AE2 framing saw pattern encoder (item, menu, screen, payload, `saw_encoder` block property, `fallback` model loader) removed with the AE2 integration.
- `compat_runtime` gradle property (false by default) adds JEI/EMI/REI/Jade to the dev runtime for testing.
- Block entity sync: update packet and chunk update tag carry marker keys (`fb_client_sync`, `fb_initial_sync`) and are dispatched by a mixin on `BlockEntity.loadWithComponents`, because vanilla has no `onDataPacket`/`handleUpdateTag`.
- Former common-setup work runs once on the first `TAGS_LOADED`; registries are registered eagerly in `FBContent.init()` in a fixed order.
- Powered framing saw energy: internal buffer stays, server config `poweredSawRequiresEnergy` (default false) keeps the saw usable without an energy mod. Session 6: optional Team Reborn Energy integration (compile-only, `suggests`, not bundled) exposes the buffer for insertion on all sides except UP, because TR Energy is the de-facto Fabric energy API and upstream exposes FE the same way.
- Shared files (mixin jsons, access widener, lang) are edited append-only by parallel agents; each task with risky mixins gets its own mixin config (render, light).
- Light: cached `BlockState.getLightEmission()` of framed blocks stays at the declared value; the per-position value is injected at each vanilla reader (own `required: false` mixin config). Fabric data attachments rejected (plain non-volatile map, unsafe for the light thread).
- Server config sync: none added, FCAP 21.1.6 already syncs SERVER configs in the configuration phase.
- Camo rotator data map: read from `data/<ns>/data_maps/block/block_camo_rotators.json` (NeoForge format) by a reload listener, resolved on `TAGS_LOADED`, synced with an own payload.
- Hit/destroy particles and break sound: own `IClientBlockEffects` registry + mixins on `ParticleEngine.crack/destroy` and the 2001 level event sound; hit handlers get a synthesized `BlockHitResult` (pos + side only).
- Overlay models (`"loader": "framedblocks_fabric:overlay"`): fixed list of 3 ids served by a preparable model resolver instead of scanning all model JSONs.
- `neoforge:white` / NeoForge warning icon replaced by own textures; `neoforge_data` keys left in JSON (ignored, emissivity handled in code); `render_type` keys ignored by vanilla.
- Block hooks (C1): NeoForge IBlockExtension hooks kept as IFramedBlock methods, dispatched by MixinExtras wrappers at the vanilla call sites (fb/mixin, fb/mixin/client/hooks); defaults for non-framed blocks in `platform/util/BlockHooks`. FabricBlock#getAppearance used directly. ItemAbility stand-in (`platform/util/ItemAbility*`) recognises vanilla axe/pickaxe classes + tags and own tools. Static FlammableBlockRegistry not used (camo-dependent flammability).
- Rails: NeoForge `isPoweredRail`/`isValidRailShape` replaced by `IPoweredRailBlock` + mixins on PoweredRailBlock, AbstractMinecart and RailState.
- Game tests run from a separate `src/gametest` source set and test mod via Loom `fabricApi.configureTests` (vanilla refuses a gametest server with zero tests; keeps test code out of the mod jar).
- Parallel fix agents work in short-path git worktrees (F:/wt/*, core.longpaths) so their Gradle runs do not collide; lead applies the diff to the main branch after review. The harness worktree isolation fails on Windows path length.
- F1-C transfer fixes go to Opus: dupe-sensitive nested-transaction semantics (precision).
- BE onLoad is deferred to the next world tick start (queue), mirroring NeoForge freshBlockEntities; Fabric's BLOCK_ENTITY_LOAD fires inside LevelChunk.setBlockEntity.
- Precision override T1 (Opus): flaky required light/occlusion gametests, cause unclear; a naive wait-longer fix could hide a real per-position light bug.
- Duplicate recipe pairs found by /fbtest recipecollision (framed_sloped_stairs vs framed_sliced_sloped_stairs_slab, framed_vertical_sloped_stairs vs framed_vertical_sliced_sloped_stairs_panel) are upstream; kept as is to stay recipe-compatible with upstream.
- Upstream src/test tree deleted (session 6): all of it except codegen/ is ported to src/gametest; codegen (upstream skip-predicate generator) is not used by the port; upstream history keeps the originals.
- Graphify graph (graphify-out/, ~98 MB) is not committed; it is excluded locally via .git/info/exclude and rebuilt with `graphify update .` (no LLM needed).
- Session 7: precision override O1 (Opus): AuxLight store is read by light worker threads while the server writes; a subtle race gives wrong light that is hard to detect.
- Session 7: T2 to Opus: same light-timing area as T1, unclear whether test-side or mod-side.
- Session 7: H1 (parallel state caches), H3, H5, H6 deferred: inherited from upstream, medium risk, not port regressions.
- Session 8: public repo is a new repository with the user's personal email rewritten (filter-branch on a bare copy); the private repo keeps the original history, no force-push.
- Session 8: CurseForge cards follow the Unified Xaero Worldmap pipeline (HTML/CSS + headless Edge); screenshots come from a dev-only showcase mode in the client test harness.
- Session 8: H6 done (makes R2 weak-value interning effective), H1 done by Opus (concurrency); H3 and H5 skipped (no measured benefit; H5 is dupe-sensitive).
- Session 8: CF1 to Opus (override): the user explicitly wants pictures matching their other mods' look; visual design quality is hard to spec for Sonnet.
